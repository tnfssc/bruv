# Integrated remote CLI transcript experiment

Fake loopback model, real die RPC/native question service, disposable Docker owner reached through pinned SSH. No real credentials, Mac, WAN, production deployment or task resumption. This extends the existing single CLI path, not the task-poc modeled-question protocol. Read wisdom/remote-workspaces/user-decisions.md.

The owner persists each complete RPC JSON event before exposing it. Its append-only hash-chained journal assigns stable sequences and serves at most 16 events per page, each at most 65,536 bytes; the client requests from its fsynced journal sequence/hash cursor (state lag after a crash invalidates stale question/completion metadata and is reconciled; state ahead of the journal or a conflicting prefix refuses) and persists each event to its own fsynced journal before advancing local state. Each sync pins the first page high-water sequence and reports observed-through that boundary; later appended events require another sync. Question status is separately observed metadata, not proof that subsequent transcript events were copied. The owner may advance immediately after any response. Sync never fetches the entire previous prefix. Page payload memory is bounded, but the journal on each side grows without automatic pruning and its in-memory offset/hash index grows with record count; budget disk and index memory accordingly. Offline/transcript reads all locally persisted conversation and tool text after SSH and owner stop. Large files are not embedded in events and need a separate transfer path; this experiment does not implement that transfer. Invalid page sequences, changed cursor, truncated/corrupt journal, excessive RPC records and owner errors refuse a complete transcript claim rather than pretending a prefix is whole. The owner keeps a bounded recent 180-event memory window for fixture assertions; its /work journal is tmpfs in this run, so durability is across process observation, not container deletion or disk crash.

Run with Bun 1.4.2 and a built die executable:

    BUN_BIN=/path/to/bun DIE_BIN=/path/to/die bash experiments/remote-cli-experience/run.sh
    bun test experiments/remote-cli-experience/*.test.ts experiments/remote-native-question-probe/*.test.ts experiments/remote-task-poc/*.test.ts

The runner checks wrong SSH host-key rejection, offline reading after tunnel loss and owner stop, launch ID deduplication, exact native question owner/version and final answer delivery. Set LAB_EXPERIENCE_STATE=/tmp/remote-state.json to retain local state; copy both /tmp/remote-state.json and /tmp/remote-state.json.events to preserve offline text (private files). Do not replay a launch after owner identity/epoch changes: acceptance and an active task outcome are unknown on owner crash, and no owner task is resumed. No automatic retry elsewhere. The native question ledger still governs answer permission. This is a small experiment, not a general remote workspace, file artifact transport, safe repository integration or production sync service.
