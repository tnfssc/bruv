# Bounded native Live frontend

This is a native human-control adapter around **src/live/extension.ts**, not a voice stack. It leaves ordinary CLI Live untouched. No TTY/hasUI fabrication, browser microphone relay, second agent, alternate credential store or model loop was added. Native audio still uses LiveAudio and the existing Google/OpenAI providers. The real acquireMainOwner stays the default.

## Integration API (runtime/frontend/CLI owner must bind)

Import **createClaudeCompatLiveFrontend(options)** from **src/claude-compat/live-frontend.ts**.

- **localAudio?: { host: string }**: explicit *operator* opt-in. The string must exactly equal node:os hostname() of the connector process. Omission or another host denies audio. This is NOT native human consent. Do not derive this option merely because T3 connected or a browser sent a command.
- **humanChoices?: boolean**, **request?: ClaudeCompatTransport["request"]**: bind a real native correlated can_use_tool / AskUserQuestion callback. Pass humanChoices:true only for a supporting native client. Missing callbacks fail closed for audio. Permission bypass modes/allowedTools must not bypass this callback.
- **notify(message, level)**: nonsecret human-visible native notices. Bind to actual frontend notification/text output, not only stderr. A hidden diagnostic sink is not a finished command UI.
- **status?(key, value)**: optional presentation. The adapter does not invent a Claude Live footer/waveform event. Do not pour its animated terminal status into a native transcript. Explicit live status uses notify and remains available without this callback.
- **dependencies?**: existing Live dependencies for tests/embedding, excluding local. Production should retain defaults for key/credentials, provider, owner and audio. No real-device/provider activation in these tests.

Return value:

- **factory: ExtensionFactory**. Install **instead of** the ordinary bruv-live factory, on the one canonical root session; never both. It registers the real live command with a native UI wrapper. Existing runtime currently installs ordinary Live; simply adding another factory gives live:1/live:2 command collisions. The actual-root test selects the native registration explicitly only to test the old composition without editing its worker-owned files.
- **capabilities()**: nonsecret deviceHost, operatorEnabled, humanChoices, localHostAudio eligibility, browserAudio:false, remoteDeviceAudio:false, model IDs and reason. Eligibility is NOT provider connectivity, helper/device readiness or successful owner acquisition.
- **stop(context): Promise<LiveStopResult>**: route native explicit Stop/interrupt through this with the canonical ExtensionContext. Cancels pending native consent and existing Live credential/device entry, calls the canonical observed Live stop port and awaits audio/provider teardown. Keep stopped:false/errors; never relabel it success. jobsUnchanged:true means voice stop does not cancel jobs. If no running voice owner exists, the existing port reports false/no owning voice session, even when this call withdrew a pending confirmation. Probe cancellation is requested, not independently verified release. Do not claim successful probe teardown from that result.
- **close(context)**: revoke future starts and call stop. Also preserve normal Pi session_shutdown/navigation events; the real Live extension owns their cleanup. Root Stop-work remains a separate existing job/foreground authority. If both are requested, await Live teardown before cancelling work.

Use the actual registered command handler through the human-only root command dispatcher. Publish **/bruv live** in command discovery/help (or the equivalent namespaced native entry); never accept it from worker/model output or as an execute tool. Bind stop/close while the canonical context is still valid. Do not install this factory for auxiliary, worker or parallel sessions; it rejects worker depth and non-rpc command starts.

Supported arguments: **status, capabilities, stop, model [exact-id], provider [google|openai], start, setup, mic-check, speaker-check**. Start/setup publishes the existing real Live status afterward (including off on failed/cancelled entry), without inventing a footer or success. Empty native arguments mean status, not the ordinary CLI toggle. An explicit start is required. Model IDs/status/stop need no audio opt-in. Native model menus paginate the five real models into 2–4-option native questions. Credential provider/setup menus reuse the existing secure setup service. No input/editor/custom terminal dialog is implemented, and keys must never enter T3 chat. Existing local editor, private live.env import and canonical provider auth storage remain the credential authority.

Every start/setup asks an exact-choice native question naming **the connector device host, selected provider/model and provider charges**, before key loading, owner acquisition, helper launch or provider connection. Denial, allow-without-answer, wrong correlation, free-text paraphrases, branch change and late replies after Stop/navigation cannot authorize resources. Device checks ask the named-host question plus the existing bounded mic/speaker consent. Browser/remote device arguments are explicitly rejected, never reinterpreted as connector-local. An explicitly opted-in server connector uses the server's devices, not the browser's. SSH/browser PCM transport is not supplied by Claude protocol.

## Concrete native ability and missing UI

Inspected unchanged official cached source **339b7bbc9e7af15560ac1201f6b9ed59b0f12f0e**, source-nightly/apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts: canUseToolEffect (around 6490–6610) accepts AskUserQuestion, produces runtime_request/turn_item human choices, returns exact answers keyed by question text and the toolUseID, and denies when no active native turn exists. Thus host consent and model/setup choices can use an actual human **command turn**, without a new browser audio feature. This inspected cache pin is not evidence for the earlier fed41fa pin in old checkpoint notes; parent must check its actual target build.

There is no terminal Live widget/waveform, browser device selector/PCM transport, persistent Live toolbar or guaranteed idle-turn Stop button in this protocol. The explicit native command path can stop Live even after start returned, as verified against the actual connector Pi session. Parent must publish those commands and bind native Stop while a turn is active; an idle toolbar is not claimed. Voice transcript/tool/wake projection and native permission/questions during later voice activity remain the composition owner's separate acceptance work. This adapter does not pretend its fake-provider start proves that presentation.

If a client lacks the active-turn correlated human-choice callback, this module only offers truthful capability/status/explicit-model/Stop controls; it cannot start devices. The exact minimal control companion would need (1) human command-turn-associated exact-choice answers for a question naming the actual host and provider cost, (2) the same canonical session identity, (3) abort/disconnect cancellation and an awaitable explicit Stop calling the real Live port, and (4) visible status/denial notices. A silent Allow or faked TTY/UI flag is not that companion. Remote/browser audio would additionally require a real audio transport/device adapter; none is included here.
