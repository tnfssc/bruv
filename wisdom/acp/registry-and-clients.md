## Findings

- The official registry is a **reviewed Git repository of install/launch manifests**, not a runtime router, agent service, trust boundary or compatibility certification. Clients download JSON and install/run third-party code locally (or in their own server environment).
- Snapshot **artifacts/acp/registry-followup.json** contains **41 agents**, no Bruv. Fresh CDN fetch at 13:03:45 UTC has exactly the same parsed JSON. Original pretty-printed artifact SHA-256 **6578af64cc7dffc9f12814f526196d8c94ab8e16fe43881677112095a9375d5e**; CDN bytes **ed1d14c501ded7f453b227994194dd258a9969ce20cc873ce0932cd7458d33dc**. Formatting explains the different byte hashes; do not equate source HEAD with CDN deployment commit.
- **T3 nightly's “Enter manually” is not unrestricted custom ACP registration.** It still resolves a real official registry ID and distribution, then replaces only its executable. A nonexistent Bruv ID will not work merely because its command exists. Registry args/env still apply. Borrowing Gemini's identity proved a clearly labelled fixture path in prior research, not an honest supported Bruv registration route.
- **Zed and JetBrains both have genuine custom command/args/env configuration, without registry admission.** Best independent acceptance host: **Zed**, for inspectable client source, custom registration, MCP forwarding, load/resume and nested-thread infrastructure. That is a recommendation for a future bounded installed test, not proof of Bruv compatibility. JetBrains is the second independent host, especially for IDE MCP; its implementation/version/lifecycle is not established by vendor documentation.
- Zed has considerably more nested-agent UI machinery than the generic T3 registry path, but **Zed metadata and session-load hooks are not a portable ACP child-task standard**. Live generic child discovery and background run ownership remain acceptance gates.

## Governance, schema, releases and security

### Admission

Create a fork and a directory matching a unique lowercase ID (letter first, then lowercase letters/digits/hyphens). Add agent.json and a **required 16×16 square monochrome currentColor icon.svg**, then submit a PR for maintainer review. No submission was made here. Registry is Apache-2.0 licensed; agent licenses/auth/billing remain their own.

Schema requires id/name/version/description/distribution; **license_url is additionally required for all IDs except the explicit dimcode exception**. Repository/website/authors/license are metadata fields worth supplying accurately. Version is plain numeric **X.Y.Z**, not Bruv's nightly string or an ACP protocol version. At least one binary/npx/uvx distribution is required. Builder checks ID/directory matching, duplicate IDs, distribution version agreement, package availability/archive HTTP accessibility, icon constraints, and rejects latest-style pins and unsupported installer formats. These checks go beyond JSON Schema alone.

Published code must actually speak ACP over the declared command. CI launches distribution(s) and requests **initialize protocolVersion 1**, checks authMethods with at least one agent or terminal method. Missing type defaults to agent; older _meta agent-auth/terminal-auth declarations are recognized. **Env-var-only auth is not the documented registry admission route**, even though clients or agents can support it. For Bruv, expose a genuine usable login/setup flow; do not add a dummy auth claim to get through CI. Terminal-auth args/env **replace**, not append to, the usual launch args/env during setup. OAuth/browser/local-callback and secure credential storage remain agent responsibilities.

### Build and update ownership

PR/push/manual workflows build indexes and launch auth verification (quarantined IDs are skipped by verifier). Successful main workflows publish to R2/CDN and GitHub Releases with date/short-SHA tags **vYYYY.MM.DD-<shortsha>**. Registry schema envelope is **version 1.0.0**, a separate concept from agent package versions and ACP protocol 1/2.

Hourly **0 * * * *** updater detects npm/PyPI/GitHub releases and commits updates directly to main, which triggers publishing. Missing GitHub repository or nonstandard asset/version layout may need manual manifest updates. It refreshes binary digests when available; agent authors still own real releases/platform coverage. Nightly protocol matrix runs **15 5 * * *** and produces reports, not a universal installed-client test. See scripts rather than assuming README's phrase “latest published” is an exact npm dist-tag contract: code enumerates published stable versions.

Default index: https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json . Immutable date/commit directories receive **max-age=31536000, immutable**; latest receives **max-age=300**. Client cache/update policy is a different layer, described below.

JetBrains consumes https://cdn.agentclientprotocol.com/registry/v1/latest/registry-for-jetbrains.json ; optional https://cdn.agentclientprotocol.com/registry/v1/latest/registry-for-jetbrains-preview.json is a complete replacement index. Source filters are client-specific: default excludes github-copilot, JetBrains excludes github-copilot-cli; JetBrains marks claude-acp bundled and appends --hide-claude-auth to its npx launch. A listing in one index is not guaranteed in another.

Optional preview manifest has only version/distribution. Accepts **X.Y.Z-preview.N** or plain X.Y.Z; highest stable/preview wins. Preview key is stripped from published entries. **Preview distributions are not launched/auth-checked, URL-probed or included in nightly protocol matrix.** Offline schema/version agreement is not stable-channel validation.

### Distribution and integrity

- Binary targets: darwin/linux/windows × aarch64/x86_64. At least one required; missing OS families warn rather than fail. No generic glibc/musl/platform compatibility guarantee.
- Binary fields archive/cmd plus optional args/env/sha256. Command is relative to extracted root. Supported upstream formats: zip/tar.gz/tgz/tar.bz2/tbz2/raw binary; installer dmg/pkg/deb/rpm/msi/appimage rejected. Specific clients may support less.
- npx/uvx fields package plus optional args/env. Package specs must pin a published matching version; distribution label describes installation intent, not an obligation for clients to spawn literally npx/uvx on every turn.
- sha256 is **optional**, 64 hexadecimal characters, and validates archive bytes against a supplied digest. Snapshot has **101 binary targets, only 53 with sha256**. TLS, optional hashes, maintainer review and successful auth handshake are not signed provenance, sandboxing, malware review or model/data-privacy assurance. Schema has no universal signed-release contract. Agent/packages/download hosts and dependencies remain trusted executable code; package-manager lifecycle scripts matter.
- Registry inclusion does **not** prove full ACP conformance, external MCP consumption, background continuation, child UI, worktree/remote placement, Stop semantics, transcript durability or backend restart/resume. Some quarantined agents can remain in the published manifest while verification skips them. Authentication declaration is not proof a real user's OAuth/login works in every client.

## Concrete viable registration plan (future work, not performed)

1. First implement a **real Bruv ACP agent executable**. Existing Bruv CLI/native integration is not that executable today. Keep stdout strictly JSON-RPC; diagnostics on stderr. Negotiate actual supported protocol/capabilities; no invented load/resume or child task support. Preserve Bruv root/child policy and cancellation/data ownership.
2. **Before public admission, use Zed custom registration**, not a borrowed official ID. Once an adapter exists, an example settings object is:

~~~json
{
  "agent_servers": {
    "bruv-local-research": {
      "type": "custom",
      "command": "/absolute/path/to/bruv-acp",
      "args": [],
      "env": {}
    }
  }
}
~~~

Use the adapter's actual required args, not an assumed current bruv acp command. For JetBrains, Add Custom Agent opens ~/.jetbrains/acp.json; equivalent agent_servers entry uses display name Bruv Local Research with command/args/env (no Zed type field). Add default_mcp_settings or per-agent use_custom_mcp/use_idea_mcp only when intended. Don't copy credentials into research artifacts/config examples. These configs are viable client routes, **not configurations tested against a Bruv adapter**.
3. Bounded future independent Zed acceptance: first prompt → streamed completion → second prompt → real Stop/cancel → reload/restart → agent load/resume, plus deterministic external MCP tool consumption and permission flow. Separately verify a late child completion while idle/new prompt and real nested session loading. Source receiving text is insufficient for Working/Stop/durability acceptance. If nested live discovery needs a private hook, document it as a Zed integration, not baseline ACP.
4. For official listing, publish a maintained **stable X.Y.Z** npm package or archive (binary SHA-256 preferred) with a real ACP entrypoint; distribution args must start ACP directly and auth setup must work in sandbox HOME. Supply actual repository/license_url/authors and 16×16 icon. **Do not publish the hypothetical @bruv/agent@0.0.1 schema example** from the probe: it is deliberately nonexistent.
5. In an eventual registry fork, add bruv/agent.json + icon.svg, validate with **uv run --with jsonschema .github/workflows/build_registry.py**, then **python3 .github/workflows/verify_agents.py --auth-check --agent bruv** in the workflow's dependency environment. Offline SKIP_URL_VALIDATION can check a draft, not prove admission/readiness. An external PR and release require later user authorization; none made now.
6. Once approved and actually present in the default CDN index, T3 nightly Settings → Providers → Add provider → official Bruv result → prepare/identity/sign-in is the supported route. For local development thereafter, manual official ID bruv plus absolute command override is possible, remembering registry args/env. Fresh cache may need official catalog opened first. Current **stable T3 v0.0.45** is not the generic registry build studied here.
7. If T3 must support unlisted local Bruv **before** admission, a true custom command/args configuration or configurable registry is a separate upstream client feature request. Patching cache/reusing another product's identity is not an acceptable supported registration story. No such feature change is part of this research.

## Small actual probe and remaining uncertainty

Ran isolated **official JSON Schema parser**, not a desktop/model/agent runtime probe: uv run --with jsonschema python .cache/acp-registry-clients/schema-probe.py. All **41 snapshot entries validated**. A hypothetical bruv stable manifest validated after adding **license_url**; numeric prerelease/nightly root version rejected. Earlier failure correctly exposed the schema's conditional license_url requirement. Schema alone accepts a package field without proving published availability or matching pin; builder/auth verifier own those checks. Probe result retained and no agent downloaded/launched by this probe.

Observed research tooling blockers: Git URL rewriting sent an attempted public HTTPS clone through SSH and reported a local key libcrypto error; stopped that owned job and fetched public commit/archive/raw APIs. A protocol tarball download stalled and was stopped; pinned raw tree/docs succeeded. No permission bypass, credentials copied or repository edits resulted. Source snapshots are plain extracted folders: git rev-parse there can accidentally return the **parent Bruv repository**; provenance uses official tag/API SHAs instead. No source assertion rests on that inherited Git identity.

Unresolved: exact published Zed build vs main behavior; generic live child session discovery; agent-initiated foreground run/Stop/persistence on Zed; JetBrains numerical ACP version, digest/cache implementation, child/late-event lifecycle and load/resume. Registry auth validation is not paid-provider auth acceptance. All these need bounded real client/adapter tests, not more confidence from listing text. **Zed is the best independent next host, not evidence that Bruv can already replace its T3 integration.**
