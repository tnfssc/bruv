## Changes and safety

- Restore Bun/pnpm download stores with a fallback scoped to tool version, OS and architecture. Exact keys still include lock/manifest or pinned upstream source/patch hashes. Installs remain frozen; source patching, dependency provenance and packaged native-dependency checks still run. Never restore node_modules, patched checkout, compiled product, web archive, HOME or credentials. This supersedes the original no-prefix policy in [download caches](download-caches-2026-09-27.md), only for content-addressed download stores. Keep pnpm key 11.10.0: pinned T3 packageManager resolves that version even though bootstrap is 11.27.1. Verified PNPM_CONFIG_STORE_DIR sets v11 store; lowercase npm_config_store_dir does not on 11.27.1.
- Isolated browser setup uses exact playwright-core 1.60.0 and --only-shell chromium, matching the unchanged gate's default headless Chromium launch. Cache only this native harness's download directory, with exact Playwright/Ubuntu24.04/OS/arch identity and no fallback. Check shared-library resolution via ldd; if a dependency is missing, install the original Chromium dependency set and recheck. Install errors, ldd errors and unresolved libraries fail. Do not upgrade an already sufficient hosted Chrome library stack/font/Xvfb set on every run. Actual executable boot/reload is still mandatory, not replaced by ldd or cached proof.
- Extend existing [exact-SHA develop artifact reuse](release-exact-sha-reuse.md) to manual releases. Lookup waits for preparation and explicitly receives RELEASE_SHA (not an overwritten reserved GITHUB_SHA variable). Both lookup and staging checkout the prepared commit; staging verifies prepared tag, SOURCE commit/tag, nonempty binaries/licenses and every binary SHA256. Existing same-repository/successful develop-push-only lookup restrictions and artifact-expiration checks remain. Browser, actual Mac binary/helper/updater and publish dependencies remain unchanged. Full release validation still runs on an ineligible/missing/expired artifact or API lookup error. Staging/provenance/download failures remain fatal, not silently accepted.

## Predicted vs proved gains

**Predicted:** where hosted Chrome libraries are already sufficient, remove apt mirror/upgrade variance: perhaps a few seconds against the 25s setup baseline, or roughly 4m against the 276s slow case. Browser-cache hits also avoid roughly 113 MB headless-shell plus FFmpeg download/extraction. Exact-SHA eligible manual releases can avoid the observed 527–540s Linux build/test/package job plus native compilation, minus lookup/download/restaging overhead. Package-store prefix reuse should improve changed-lock/patch runs, but its hosted hit rate/savings is not yet measured. No runner-time savings are presented as wall-time savings.

**Limits:** no new hosted run was dispatched. Manual preparation often creates a new commit with version/notes changes, which cannot reuse the earlier commit's outputs; immediate parallel develop/manual runs and still-running dry runs remain separate full builds. This change does not wait/poll for pending runs or reuse “nearly identical” commits. Run 36750929320 would correctly take a full build because no eligible dry run existed at b86f17f. Reuse mainly helps already-prepared develop commits with complete notes and a successful dry run. CI build/test timings are not proved faster by this branch. No test selection/concurrency/resource policy was changed to manufacture speed.
