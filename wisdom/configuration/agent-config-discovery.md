## Candidate future design — NOT decided

1. Read-only discovery first: typed `config.describe()` (or equivalent) lists supported keys with label, type/enum, default and effective nonsecret value, source/scope, path category, availability (TUI/headless/remote), reload/restart/future-task applicability, humanOnly flag and reason. `config.get(key)` reads permitted nonsecret values. Distinguish configured, effective, unavailable, unknown and verified auth; no paid-provider requests just for discovery. Group Pi, die, session, project and remote-host options; don't misclassify utilities.
2. Only after an explicit authority decision: narrowly allowlisted `config.set(key,value,{scope})` using existing validators/owners and reporting old/new/scope/apply time; no arbitrary JSON/path mutation. Current human-only routes are an inventory fact, not a settled future policy. The user wants agent parity for configuration, including slash-menu settings. Determine how authorized agent changes can cover login/logout, SSH connect, grants/revokes and trust without self-escalation; do not carry current restrictions forward by default. Human question answers and approvals must not be fabricated by the agent. Cost/provider choices need explicit authorization policy, not mere type validation.
3. Ship guide inside release assets at stable offline path; let discovery point to it. Brief prompt pointer, e.g. “Configuration options and limits: bundled guide at <offline path>; matching online copy at <pinned URL>.” Online link shape `https://github.com/tnfssc/die/blob/<release-commit-sha>/docs/agent-configuration.md` **only if that file exists at that exact release commit and matches the embedded copy**. Current HEAD `56450143e17cc5f0059ebf4eaa8ba2f2f2024bbe` cannot pin a future uncommitted guide. This research note is not the guide.
4. Prefer metadata registry for die-owned fields checked against handlers; Pi adapter/version audit rather than duplicate behavior claims. Generate schema/docs where reliable; hand-annotate privilege, scope and apply semantics. CI inventory checks registered command and settings IDs, no secret fields, pinned URL/ref and embedded Markdown hash. Test actual binary offline with network disabled, TUI/headless views, denials and restart/reload; static discovery isn't live auth verification.
