# Remote task-owned text artifacts

The module exports a fixed allowlist: taskDir/session.jsonl and session.jsonl.artifacts/execute-*/{stdout,stderr}.log. The server must call it only after owner/epoch/task fencing in the owner control handler; these functions do not authenticate a request or establish the taskDir themselves. Client control pins ownerId and epoch and writes under the local remote client directory's artifacts/taskId. Both catalog and chunk checks bound each file at 10 MiB, total at 128 MiB and count at 256; chunks are 256 KiB. Changed files invalidate the advertised digest and require a new catalog/sync. Manifests are incomplete until each file is verified, and stale files are not listed. The parent must wire the artifact protocol and sync snapshot.

Background shell/native job output is not generally recoverable as full task-owned files: TaskManager appends output into a bounded in-memory buffer (src/tasks/task-manager.ts #append) and agent progress filters raw chunks. Inspect responses can lose prefixes. No safe task-owned full-output file reference was found from the remote owner; harvesting ~/.die session directories or machine-wide logs would cross task ownership. Add a task-owned output persistence hook in TaskManager/owner first if full background output is required. Execute spill files and the owner session journal are covered, but a 10 MiB file or 128 MiB total cap explicitly makes larger captures unavailable through this transport.
