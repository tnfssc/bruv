# Disposable SSH transport proof (2026-09-26)

Run: ```sh
bash experiments/remote-ssh-probe/run.sh
```

This is an experimental Docker/Linux localhost fixture, **not a Mac test**. Owner is the existing fake-provider `experiments/remote-task-poc` implementation, staged with `dependency.ts`, bounded-log, Bun and packaged die. The staged binary is 0.15.3, SHA256 `2cc2c23454d110ffcdb9701420aa3e07af2ac629443c966ac92c99bbc458afea`; repository release metadata says 0.15.4. No paid provider or model authorization. SSH server is a disposable OpenSSH Debian image and shares only the private owner network namespace; remote SSH forwarding destination is owner's loopback:8080. Only SSH:2222 is mapped to a Docker-assigned host **loopback** port. The owner begins independently, before SSH authenticates. A separate per-run Docker bridge network scopes the containers; only the SSH listener is published to host loopback. No existing machine is contacted over SSH.

The runner generates ephemeral client/host/wrong keys and private known_hosts under a mode-0700 temporary directory, cleaned even on failure. SSH uses `-F /dev/null`, explicit identity and `IdentitiesOnly=yes`, `IdentityAgent=none`, no agent forwarding, strict host key checking, explicit known_hosts and disabled global known_hosts and key updates. It asserts a deliberately wrong pinned host key is rejected *for host-key verification*, not just connection refusal. No user's ~/.ssh is read or mutated; no key material printed or committed. Dynamic local forward ports are selected with bounded collision retries and `ExitOnForwardFailure=yes`.

Client hello/profile (fixture launch), task launch, duplicate retry, and incremental durable event sync use **only the SSH local forward**, never Docker host owner HTTP. Runner kills the SSH process after an observed tool start while owner runs; verifies client cannot reach owner without forward; waits without client; reconnects and catches up. It stops both containers and reads full cached tool and assistant transcript offline, using task-poc's transcript validator. Timings are host monotonic elapsed cold forward setup + hello, and warm reconnect + catchup separately, not wire latency or packet bytes. Task-poc verification enforces three fake-provider model turns, two successful tool results and final done; transcript persistence uses its fsynced replica. This does **not** show provider behavior, real remote provisioning, hardened remote account, Mac integration, network-wide cut (the owner remains alive), power-loss atomicity, or once-only side effects on crash. SSH process kill severs only the client forward; it does not terminate owner.

The runner bounds image builds at 150 s each, tests via finite polls and removes its scoped images, containers, network, volume, keys and replica on success/failure. Docker daemon/image package install still requires local Docker and apt access; observed installation failures should be reported, not fixed through changes to user or host SSH configuration. Values in `wisdom/values.md` remain unchanged: this probe adds evidence of transport separation, not a new general invariant.
