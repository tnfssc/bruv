# Remote SSH jobs normal-CLI integration proof

Opt-in: after building the **integrated** tree, run `DIE_REMOTE_JOBS_E2E=1 DIE_BIN=$PWD/dist/die BUN_BIN=/path/to/bun bun test tests/remote-jobs-e2e.test.ts` (replace the NUL delimiters with backticks). This reuses `scripts/remote-e2e.sh`: ephemeral Docker SSH owner, loopback pinned host key, throwaway HOME and local fake OpenAI-compatible provider, built CLI on both sides. No installed fake provider, real credentials, release, push, or production SSH host. The owner fake provider has separate delayed A/B job markers so model replies and server terminal transitions can be distinguished.

`scripts/remote-jobs-e2e.ts` launches two independent RPC parent sessions (explicit session files) sharing one remote connection/cache. Each model actually invokes `execute` with `remote.launch`; each parent responds and yields while the owner background shell continues. It verifies remote terminal states, then requires each original parent to receive an actual `message_end` with `customType: task-complete` and a subsequent model ACK. The task-complete envelope must not contain the other session's task ID. Repeated sync must not produce duplicate completion messages; disconnected/reconnected sessions must not replay them. This is not satisfied by a remote UI dump or standalone `die-remote` follow-up. Existing `scripts/remote-e2e.ts` proves owner continuation after client death and offline transcript, but **did not prove** parent wake: its original parent was killed before completion, and its reconnect is an unrelated session.

Current observation (2026-09-27): proof harness and isolated test compile/bundle; integrated CLI Docker execution still pending parent integration/build. Therefore parent wake, at-most-once across restart, and isolation are expectations, **not yet observed passes**. Even a passing run would not prove atomic exactly-once recovery across crash during delivery, all transient SSH failures, or stopWork offline/partial behavior. Values unchanged: existing guidance to show true observed state, preserve human authorization and avoid extra notification systems already covers this lesson.
