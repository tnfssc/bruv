# Remote SSH jobs normal-CLI integration proof

Opt-in after building the integrated tree: DIE_REMOTE_JOBS_E2E=1 bun test tests/remote-jobs-e2e.test.ts. This reuses scripts/remote-e2e.sh: disposable Docker SSH owner, loopback pinned host key, throwaway HOME, built CLI on both sides. Both fake provider models (remote worker and fixture-parent) run **inside Docker**, with provider port published only on host 127.0.0.1. The host harness does not run a fake provider. No real credentials, installed provider, release, push or production SSH host.

scripts/remote-jobs-e2e.ts first exercises normal compiled print/JSON CLI execute -> remote.launch -> yield -> task-complete -> parent ACK. Then two RPC parents with distinct durable session files share one pinned SSH connection/cache. Both models actually invoke execute/remote.launch, yield while remote jobs continue, receive task-complete messages and respond with parent ACKs. Neither envelope may contain the other session's task ID. Repeated sync and reconnect may not redeliver completion. Docker markers separate server work/terminal transitions from parent model responses. This cannot pass from a die-remote UI dump or standalone remote followup.

Observed 2026-09-27 on the integrated binary: the Docker script passed print/JSON, two-parent completion and isolation, repeated sync and reconnect. A wrapper initially failed only because its expected PASS string lacked the newly added print/JSON prefix; corrected. Earlier scripts/remote-e2e.ts owner-continuation proof did not establish parent wake: its parent was killed before completion and the reconnect was an unrelated session.

Passing this controlled run does not prove crash-atomic exactly-once acknowledgment, provider/network fault universality, or real macOS/Live audio. Unit tests cover offline stopWork partial reports, durable claim uncertainty/retry and question/capability human-only waits. See jobs-integration.md for the explicit host dispatch acknowledgment limits. Values unchanged; existing proof/ownership/human-authority guidance applies.
