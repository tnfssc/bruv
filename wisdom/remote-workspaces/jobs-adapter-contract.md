# SSH jobs adapter contract (parent integration)

Import `createRemoteJobsAdapter(client: RemoteClient)` from `src/remote/jobs.ts`. Pass adapter as final optional `JobService` constructor parameter. Service resolves session file using `ctx.sessionManager.getSessionFile()`, calls adapter `list(sessionFile)`, `inspect(sessionFile,id,offset,limit)`, `stop(sessionFile,id)`, `stopWork(sessionFile)`. SSH IDs use `ssh:<base64url(UTF-8 taskId)>`; no unprefixed SSH fallback. Adapter only sees tasks with `RemoteTask.jobSessionFile === sessionFile` and pinned ownerId/epoch. SSH launches from agent sessions must pass `sessionFile` as optional final argument to `RemoteClient.launch(repoPath,prompt,taskId?,overrides?,sessionFile?)`; it is persisted before network, and retry cannot reassign existing task. Human launches without sessionFile remain unowned and not jobs-visible. Do not wire standalone wake; parent owns durable completion outbox.

Lists are cached observations, explicitly mark stale/unknown and do not claim live discovery. StopWork reports partial when owner offline or uncertain, never implies a pending cancel finished. Methods input, closeInput, snooze, setWatch reject SSH IDs. Cursor ordering local then native then SSH; SSH pagination applies only to session-owned cache.
