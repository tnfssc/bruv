# Native remote reply integration (2026-09-27)

Production owner retains the RPC session after a native question checkpoint. Controller records a targeted answer intent (task, question ID, branch/session owner, version, text and stable reply ID) before acknowledgement; owner marks a single dispatch uncertain on disk before sending an internal RPC extension command. Extension invokes QuestionService.answer with that owner/version/reply ID, claims delivery and queues a new follow-up parent turn, not answer text as an RPC stdin user prompt. Verified response plus native question ledger marks delivered; failed, missing or late evidence stays uncertain. Terminal records cannot be overwritten by late reports. A pending human question keeps its owner alive beyond the usual RPC deadline; a dispatched answer still has a bounded settlement deadline. On exit, unresolved questions make task unknown, not done.

Client persists reply ID before SSH, rejects conflicting retries and retains offline observations. Bounded rotating polling syncs active tasks on session start and periodically, with nonblocking normal-session notification for changed questions/terminal state. Explicit model/thinking overrides are pinned to launch intent; normal profile remains default. The human command handles answer; agent execute cannot forge a targeted human reply. The typed bridge and prompt description in src/typescript/job-bridge.ts and src/prompts/execute-description.md still need parent integration for model/thinking overrides and user-facing status. Live remains execute-only.

Evidence: Docker no-network Bun image, bind-mounted source/dependencies/assets: TypeScript check and 15 focused remote owner/client/extension tests pass. Tests cover stale owner/version, persisted duplicate intent and conflict, lost answer acknowledgement/stable reply ID, bounded polling, and a protocol fixture that dispatches a mailbox answer, verifies the native-command route and reads a delivered ledger. This is not proof of full native runtime/provider continuation; integrated Docker native-question E2E remains required before claiming production acceptance. No real SSH host/provider used.
