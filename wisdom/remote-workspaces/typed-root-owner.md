## Why these seams
Pinned SDK 0.99.1 runRpcMode uses the normal AgentSession and extension factories; prompt gets authoritative preflight disposition, get_state returns actual model/settings/session file, abort is normal root abort, clear_queue removes scheduled user turns, EOF disposes runtime and gives process exit. SDK extension dialogs emit extension_ui_request and wait for extension_ui_response without acknowledgement. Pi InteractiveMode has no public attach remote existing session API. Detached owner therefore keeps normal installed CLI --mode rpc open, not a child-profile agent or local coordinator. A private authenticated Unix IPC socket in the actual root extension exposes trusted human/native facets; no registered command/tool/helper conveys human answer authority.

## Owned files and semantics
- root-store.ts: FULL synchronous WAL SQLite acceptance/request IDs + exact canonical intent, command journal/claims before any dispatch, ordered bounded event journal, explicit retained cursor gaps. Up to 100 root records and 10,000 command receipts/root retained; no universal scheduler/automatic garbage collection or replacement.
- root-owner.ts: reuses existing installed SSH hello ownerId/boot epoch. Create-or-resolve launches once; detach only presentation. Owner PID plus Linux process-start stamp fences liveness/PID reuse. Missing/crashed owner and pending dispatch become unknown, never replayed/replaced. Startup verifies destination normal model and explicit exact provider/model + thinking; no profile fallback. Close clears queued prompts, uses actual native jobs.stopWork and complete paginated child inspection, then only EOF + confirmed exit0 records closed. Exit acknowledgement timeout stays unknown; no source export from unknown/nonzero.
- root-runtime.ts: SessionHost-equivalent actual job service facets and actual configured QuestionService.answer pinned id/owner/version/text/replyId. Normal configured onAnswered owns continuation/SSH mirror dispatch; backend never duplicates its turn. Private IPC must be stripped from execute/shell/child environments by lead (not an agent helper facet).
- root-entry.ts: one bounded JSON SSH request and flushed response. No provider/tool loop on the client.
- root-contract.ts adds ui.respond for full normal select/confirm/input/editor SDK dialogs. Exactly one string value/boolean confirmed/cancelled:true field; pending request ID/method must match. Response pipe write returns delivery:written, applied:unknown because SDK has no applied ack; same durable command ID never sends it twice.
