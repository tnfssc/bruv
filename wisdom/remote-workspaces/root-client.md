# Root client is a presentation, not a child or a provider

The placed CLI must invoke runRemoteRoot before any local provider/auth/model/tool/session startup. An empty local provider configuration is valid. The named target must be resolved only from previously human-authorized RemoteClient state; target injection is an internal CLI resolver seam, not an arbitrary host flag. rootSshTransport speaks one bounded JSON request using --remote-root-control, no remote TTY, tmux, shell session, credential transfer, or local coordinator.

RootClient persists a private pointer per canonical current source directory + named destination under ~/.die/remote/roots. That points to an immutable owner/epoch/root role/depth0/session/source/model intent. Source capture is current tracked state in an orphan baseline, not Git history. Explicit approved untracked paths pass captureRepository validation and capture those bytes; all others are omitted and reported. Explicit server-existing repositories are labeled honestly, never advertised as current-source parity. Workspace isolation is separate from placement/source.

Command identity and exact intent are fsynced before dispatch. A reply loss is unknown, not failure-to-launch. On restart, command-status reconciles that SAME saved identity. Unknown/not-found receipts never trigger automatic replay. Startup prompt identity is also persisted so repeating the same placed startup invocation cannot duplicate it. A different startup prompt on a saved root is rejected; use its editor (or explicitly fresh root). Prompt typing is blocked while another prompt receipt is unresolved. Abort is a dedicated command; closing the terminal detaches only. /close closes the server root explicitly and source return waits for authoritative closed + exitCode 0.

Observation validates contiguous sequence pages before committing cursor. A gap preserves the authoritative record, reports the gap, and does not invent missing events or advance the cursor. Local event cache is bounded; authoritative messages replace the projection. Cached messages are only presentation state, not model history. RootControls uses normal Pi Editor and QuestionPicker human choices for /questions and job list/inspection/confirmed cancellation for /ps, not remote inbox UUID workflows.

Source integration calls integrateRepositoryResult against the original source directory/baseline under a repo SQLite lock. Changed HEAD/index/work, complex changes and remote untracked changes remain explicit review artifacts. The source return target is the runtime that initiated this root, not a hardcoded laptop. Receipts fence repeated applications; closed result remains durable on reconnect.

Tests use injected typed transports and isolated fixture directories. No real SSH targets, credentials, provider APIs or recording are needed. A combined terminal proof must still use the actual server runtime + CLI wiring after backend/frontend source integration; unit tests are not that proof.
