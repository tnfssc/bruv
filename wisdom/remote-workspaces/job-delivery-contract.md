# SSH job completion delivery contract

The remote extension/ownership adapter publishes **owned** observations into `src/remote/job-events.ts`, scoped by parent session file. Each snapshot includes pinned ownerId and epoch, taskId, state (running/unknown/done/cancelled), optional preview, and actionable question/capability wait. Publish only verified remote state: unknown/offline is never terminal. Do not publish globally cached unowned tasks. Call `remoteJobEvents(sessionFile).publish(observation)` after refresh/launch, and `.snapshot()` for the print boundary. This module does not access the SSH client. Ownership/adapter wiring is implemented in job-observations.ts and both extension launch/refresh seams.

The agent extension subscribes per active session, and submits terminal observations to a SQLite outbox before adding a remote item to the shared completion batch. The terminal key is parent session + pinned SSH ownerId/epoch + taskId, **not** artifact/transcript state. Repeated refreshes cannot create another row. The delivery envelope ID is stable across retries. Synchronous dispatch success marks delivered; a crash between dispatch and marking leaves an uncertain leased row that can replay with the same ID after 30 seconds. This is not an end-to-end acknowledgment or exactly-once guarantee; see jobs-integration.md for the possible Pi queue crash-loss window. Failed synchronous dispatch is retried with bounded exponential delay; after the bound it remains inspectable and replayable on session restart. Do not infer delivery from refresh or UI rendering. T3 native delivery must not fall back to unowned Pi turns.

Actionable waits use the same durable outbox with a payload fingerprint; pending attention is superseded by terminal completion. Claims fence concurrent senders; dispatch failures retry up to eight attempts, then remain replayable on restart.

On session shutdown unsubscribe and release timers/database. Print/json boundary checks both local tasks and owned remote running/unknown tasks, subscribes then rechecks to close the finish-before-subscribe race; actionable waits wake through the shared batch, not authorization. Unknown never generates a completion. Live and local TaskManager retain their existing paths. The event source is session-scoped; ownership verification must occur upstream.
