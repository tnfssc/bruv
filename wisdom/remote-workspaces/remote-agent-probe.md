Scope: [experiment](../../experiments/remote-agent-probe/README.md), branch `die/real-agent-loop-remote-placement-probe-3f1110f2`. Read `wisdom/values.md`, `rpc-agent-demo.ts` and remote workspace notes. No production edits. The original local demo established RPC + fake-model feasibility; this probe moves the **owner and actual die process** inside isolated Linux Docker, not just shell execution. The short-lived host client detaches before first tool result and starts a separate reconnect viewer after the autonomous second call.

Run `BUN_BIN=/home/tnfssc/.godie/runtimes/bun-1.4.1/a140e66e514c0807/bun DIE_BIN=/home/tnfssc/Code/die/dist/die bash experiments/remote-agent-probe/run.sh`. Docker image build/pull plus copy takes ~20s; agent loop ~4s. Initial run: PASS, detached 317ms, second model turn 3462ms, done 3701ms; 3 synthetic model turns, 2 real execute tool calls. Repeat with final-message assertion: PASS, detached 316ms, second model turn 3443ms, done 3691ms; transcript includes final assistant response.

Client is a Linux host process, **not a Mac**. No SSH, provider, multi-agent load, or on-demand Mac capability is tested. Transcript is fetched via HTTP and optionally written client-side; container-memory transcript disappears on container exit. Closing a viewer doesn't close owner here, but container shutdown does. To prove a Mac capability next, design authenticated allowlisted on-demand tool invocation with bounded response and offline/reconnect semantics; do not interpret remote arbitrary host tool access from this test. The local HTTP+token route is a lab adapter, not a production authentication protocol. Values unchanged: existing emphasis on genuine evidence, simple scope and explicit gaps covers this lesson.
