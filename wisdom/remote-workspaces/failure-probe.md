# Failure boundaries: actual socket loss and owner SIGKILL (2026-09-26)

Experimental only. See `experiments/remote-failure-probe/`. On Linux Docker, staged packaged die 0.15.3 SHA256 `2cc2c23454d110ffcdb9701420aa3e07af2ac629443c966ac92c99bbc458afea`; repository release metadata 0.15.4 is not the binary under test. Bun host 1.4.2; owner Bun staged from host. No production changes, paid model, Mac capability, credentials/home/socket mounts. Separate container/image/volume and random loopback port per experiment; capped resources and bounded waits; runner cleans its Docker resources.

Gate forwards a real POST /launch, receives the owner response *after* fsynced acceptance and destroys the client connection without forwarding any response bytes. Measured gate: 377 request bytes, 393 upstream response bytes, **zero downstream response bytes**. Client received ECONNRESET, no launch JSON. Independent owner events show one acceptance; retry of the exact stable ID/prompt/profile resolves to the same config and reports duplicate. Before kill: one model turn, execute start, no execute end or outcome. This proves the missing ambiguous-delivery edge, not once-only side effects across a crash.

SIGKILL of the owner container during the in-flight die RPC execute, then start on retained volume: owner identity retained, epoch 1 -> 2, one accepted event, one model turn, unknown outcome (not done or failed); retry remains duplicate, no RPC replay. Old-epoch replica refuses sync with explicit reconciliation required. An incomplete replica JSONL line causes offline read to fail, and the intact canonical replica stays readable. No automatic repair or resumed turn claimed. Process kill can leave completed-but-unrecorded side effects; their state is unknown and cannot be undone or safely replayed. Separately the prior task-poc fixture runs with client process gone while remote proceeds to three model turns, two tools and persisted done; offline transcript reads it after container stop.

Limits: test fixture only, narrow fault positions, app socket bytes (not packets), fsync is not a power-loss transaction; provider delivery and cross-epoch reconciliation, local capability/question flow and general cancellation/repair are unproved. Existing values in `wisdom/values.md` cover truthful unknown state, one owner, stable retry identity and no quiet transcript loss. Do not build a recovery framework from this probe alone.
