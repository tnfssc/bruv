# Local capabilities for native remote tasks (2026-09-27)

This slice adds `src/remote/capabilities.ts` and Docker-run tests. It is a reusable module, **not yet wired** to native remote owner/client or a claim that a live remote task can call local tools. Existing execute remains Live-only. The transport/owner worker owns that integration. No release, install or push.

Integration hook: on the client, after the user chooses a local repo root and names each allowed kind, register trusted local `tool:name` / `skill:name` handlers and call `clientCaps.grant(taskId, absoluteRepoRoot, kinds)`. Never grant from cwd or an owner-provided path; never copy local config, environment, SSH agent, credentials or arbitrary tool registry. Send only grant ID, task ID and names to the pinned owner at task acceptance. On the owner, call `ownerCaps.allowOwnerGrant(id, taskId, kinds)` only for that accepted task. During remote execute, await `ownerCaps.request(id, taskId, kind, input, taskAbortSignal)` and record the request ID and waiting state in the owner's durable event journal before exposing it to the client. While offline, leave it waiting; do not infer denial or success. On authenticated reconnect, the client validates pinned owner ID/epoch/task/request, calls `clientCaps.serve(request)`, persists the reply intent **before** sending, and sends the same request/reply on ambiguous delivery. Owner validates IDs and calls `submit(reply)` once; journal resolution before ACK. End/revoke calls `endTask`/`revoke` on both sides. Transport and journal replay/dedup are not supplied by this volatile module. Owner restart without recovered request state is unknown, not a fabricated answer. Revoking a grant while an external handler runs suppresses its reply but cannot undo handler side effects.

`repo.read` is a fatal UTF-8, maximum 16 KiB read of a relative file under the canonical selected root; rejects parent traversal, symlinks in the path, nonregular files and oversized files. Fixed buffer bounds reads even if the file grows. Node path operations do not prove confinement against a hostile process concurrently swapping ancestor directories. Do not offer this as a hostile filesystem sandbox; harden with descriptor-relative platform APIs if that is a requirement. Named tool/skill handlers are trusted, explicit callbacks, not remote shell; handlers must themselves enforce domain-specific authorization and cancellation. Max 32 pending requests, 4096-byte inputs, 16 kinds per grant, 16 KiB outputs; no timeout while offline unless user cancels. No machine-wide grant exists. The user must opt in again after process restart.

Docker (network off, mounted Bun 1.4.2) ran `bun test tests/remote-capabilities.test.ts`: 4 passed, 23 assertions. Covers grant/revoke, per-task and kind checks, path and size denial, offline wait, lost-reply retry, stale reply, cancellation and handler output bounds. Full native SSH/provider/Mac round trip and owner crash recovery remain unproved. Values unchanged: leave user work safe and show what is real already cover explicit grants and honest waiting; this note records the narrower integration recipe and proof boundary.
