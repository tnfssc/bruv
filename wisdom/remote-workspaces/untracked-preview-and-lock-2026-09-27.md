# Bounded untracked preflight and private lock creation

Menu and human repository launch inventory now use `-z`-delimited git output through a bounded 1 MiB stream (`-z` in this document means the NUL delimiter). A truncated inventory exposes only a short preview and a **lower-bound** count; it cannot approve all paths. Tracked-only proceeds; explicit `include` still goes through the existing backend snapshot guards. The backend has not changed. Seam for the concurrent menu improvements: `src/remote/untracked-preview.ts` exports the inventory helper; menu code only consumes `paths/preview/count/incomplete`. Do not render `count` as exact when `incomplete` is true or offer bulk approval for a truncated inventory.

Daily dogfood found that closing another descriptor on the SQLite lock inode releases *all* process POSIX locks on that inode, even locks held by a different SQLite connection. For new lock databases only, synchronize the exclusive `openSync(path, "wx", 0o600)`/create and close before opening SQLite. EEXIST must skip opening the inode entirely; do not chmod via an additional descriptor or open/close an existing lock. No JS interleaving is possible during this synchronous creation. Existing cross-process SQLITE_BUSY regression plus mode checks on first and reused connects cover both properties.
