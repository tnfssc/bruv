# Native question ownership: diagnostic sibling (2026-09-26)

A question created inside a persisted execute call belongs to the assistant tool-call journal node. Successful execute exit appends a custom/die-diagnostic child before the actual toolResult sibling; the active conversation follows toolResult. QuestionService previously treated the first chronological child as the only permitted continuation. RPC /questions answer acknowledged the command but notified “Question not found for owner branch”; the ledger stayed pending. SDK-only tests lacked this journal shape.

QuestionService now excludes only custom/die-diagnostic when selecting the first meaningful child and deciding whether a leaf has meaningful descendants. Ordinary custom entries, messages and toolResults still constrain ownership. Tests construct the actual sibling order, answer and retry with a stable reply ID, reject a genuine sibling fork, and check diagnostic-only root/anchor versus ordinary custom children. Ancestor navigation still cannot write once a real child exists.
