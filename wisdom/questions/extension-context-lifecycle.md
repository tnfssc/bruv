# Question status refresh and SDK context lifecycle

Pi SDK 0.99.1 invalidates an extension runner context during session replacement/disposal. Its `assertActive()` throws the explicit `This extension ctx is stale after session replacement or reload.` error; this can happen before an asynchronous extension callback resumes, even when the callback still holds the same context object. See `node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/runner.js` (`ExtensionRunner.invalidate/assertActive`) and `dist/core/agent-session-runtime.js` (`teardownCurrent` emits shutdown then disposes the old session).

Question background refreshes intentionally keep ordinary failures visible as `/questions unavailable`, but must not let the SDK stale-context lifecycle exception escape while trying to update that status. `src/questions/extension.ts` ignores only that recognized SDK error; other UI errors still propagate. The generation/context check continues to discard work completed after `session_shutdown`. Regression coverage in `tests/questions-extension.test.ts` exercises both invalidation during failed refresh and refresh completing after shutdown. This is lifecycle cleanup only; it does not alter remote question ownership, human-reply checks, or source-approval handling.
