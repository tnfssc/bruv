## Web: browser preferences versus thread state

Paths below are relative to the pinned T3 checkout unless prefixed src/ (Bruv root).

- apps/web/src/composerDraftStore.ts: COMPOSER_DRAFT_STORAGE_KEY is localStorage key t3code:composer-drafts:v1. partializeComposerDraftStoreState serializes stickyModelSelectionByProvider, stickyOptionsByModelByProvider and stickyActiveProvider, as well as retained draft content/context/modes. persist merge normalizes and rehydrates them. This is browser-origin-local persistence, not a server-global preference or portable account preference. Draft keys are environment/thread scoped; sticky picks are provider-instance scoped, and options additionally model scoped.
- components/chat/TraitsPicker.tsx, TraitsMenuContent.updateModelOptions calls setProviderModelOptions with instanceId, model and persistSticky:true. composerDraftStore.setProviderModelOptions updates current draft selection and remembered options for that provider instance/model. ChatView.handleModelChange reads stickyOptionsByModelByProvider[instanceId][resolvedModel]; a model with no remembered options starts at its default, rather than inheriting another model's options. applyStickyState seeds a new draft from sticky selections (including their options). This already saves thinking and other descriptor-backed model options; exclusion from an earlier model fix did not mean unsaved.
- Bruv agent instruction mode is a model option named instructionMode, not plan/default interactionMode. Canonical patch apps/server/src/provider/Layers/PiProvider.ts, piModelsFromSettings adds fast/normal/orchestrator descriptor, default orchestrator. It uses the same option persistence above. orchestration-v2/Adapters/PiAdapterV2.ts applies actual /mode through Pi RPC before a user turn; not a separately invented thread/global field.
- hooks/useHandleNewThread.ts and lib/chatThreadActions.ts, resolveNewThreadModelSelectionOverride: explicit project model pin > explicit carry from a different draft > sticky picker preference > environment fallback. A resumed thread's ordinary saved model does not become explicit carry. Existing thread model/options remain its own state; local composer overrides take precedence until committed.
- Runtime permissions and plan/default interaction mode are saved too, but NOT as last-used global sticky defaults. composerDraftStore.setRuntimeMode/setInteractionMode retain them per composer draft; ChatView.handleRuntimeModeChange/handleInteractionModeChange stage changes locally (and update a local draft shell). ChatView.persistThreadSettingsForNextTurn sends changed permissions/mode to server before the next turn. Reload can restore unsent local choices in the same browser. Server thread state restores sent values, including modelSelection/options, runtimeMode and interactionMode. orchestration-v2/ProjectionStore.ts persists projection/thread payloads in orchestration_v2_projection_threads; persistence/Layers/ProjectionThreads.ts also implements those fields for the existing projection layer.
- ChatView resolves runtime as composer override > existing server-thread mode > project/environment default. Interaction is composer override > current thread mode > DEFAULT_INTERACTION_MODE; useHandleNewThread carries current interaction mode into a new draft. No server/global defaultInteractionMode setting was found. A completely fresh unrelated draft defaults to default interaction mode unless carry/draft context supplies it.
- Draft serialization deliberately drops orphan draft sessions, not live mapped/promoting/content-bearing drafts. Mode-only settings on a retained mapped blank draft are serialized. Do not infer that empty text means choices cannot persist.

## Web: server/project/workspace configuration

- src/t3/web/launcher.ts webLaunch defaults base dir to ~/.bruv/web; seedWebSettings reads/merges <base>/userdata/settings.json, preserving other root settings while setting the Bruv provider executable. T3 apps/server/src/config.ts uses <stateDir>/settings.json and <stateDir>/statev2.sqlite. With the default launcher these are ~/.bruv/web/userdata/settings.json and statev2.sqlite. Explicit base-dir changes the location.
- apps/server/src/serverSettings.ts reads/writes settingsPath atomically. packages/contracts/src/settings.ts defines defaultModelSelection, defaultRuntimeMode, defaultThreadEnvMode, newWorktreesStartFromOrigin and projectSettingsOverrides. packages/shared/src/projectSettings.ts resolveProjectSettings overlays explicit project overrides onto environment settings; sources identifies project versus environment. Disabled-provider model overrides do not apply. Project settings are therefore durable server configuration, not browser sticky picks.
- Workspace intent is separate from child model profiles. packages/shared/src/threadEnvMode.ts resolveDefaultThreadEnvMode: explicit caller/composer choice > project setting > checked-in t3.json defaultThreadEnvMode > global server default (local). hooks/useHandleNewThread.ts consults lib/t3ProjectFileDefaults.ts for that file. Retained local draft shells save envMode, branch, worktreePath and startFromOrigin; project/environment retarget clears machine-specific branch/worktree paths but retains machine-independent intent. Existing threads retain their workspace context.
- CLI src/tasks/worktree-workspace.ts readWorktreeSetup reads repository t3.json scripts/runOnWorktreeCreate. Setup is repository configuration, not a model/child profile; current policy automatically runs setup. Workspace selection inherit/worktree is launch intent with durable task/session/workspace metadata, not a new global last-used-model setting.

## CLI: global defaults, model-specific overrides, and resume

Dependency inspected: @earendil-works/pi-coding-agent 0.99.1 under node_modules (dist/core/settings-manager.js, sdk.js, agent-session.js, main.js, modes/interactive/interactive-mode.js). scripts/prepare-assets.ts configures packaged Pi name/configDir to bruv/.bruv; installed dependency's standalone config defaults to .pi. Bruv global defaults normally reside in ~/.bruv/agent/settings.json (BRUV_CODING_AGENT_DIR can relocate agent dir); project overrides are <cwd>/.bruv/settings.json. SettingsManager.create merges project over global. Its default setters mutate global settings, not project overrides.

- src/agent/last-used-cli-model.ts registerLastUsedCliModel saves defaultProvider/defaultModel through SettingsManager on non-restore root TUI model_select. It excludes children and automation; resume/restore does not rewrite startup defaults. Normal root /model selection and cycling therefore already save future-session model defaults. This supersedes the older initial fix note's CLI-only-Ctrl+S description.
- Pi SettingsManager also supports global defaultThinkingLevel and provider/model-specific modelThinkingLevels[provider/model]. Interactive /settings explicitly edits these persisted defaults/overrides. Ordinary /thinking selection and cycling call AgentSession.setThinkingLevel without persist:true: session transcript thinking_level_change is saved, not global default. Thinking selector's save-default action passes persist:true (Ctrl+S). Existing code emits thinking_level_select on effective changes; no equivalent Bruv last-used-thinking listener is registered in this baseline. That is the real automatic last-used-thinking gap owned by task_1ab23236, not loss of all thinking persistence.
- main.buildSessionOptions applies explicit --model / --thinking (and scoped-model choices). sdk.createAgentSession uses explicit options first; with an existing message-bearing session it restores recorded model and thinking. New-session thinking: provider/model override > global default > built-in default, clamped to capabilities. Resume thinking with no recorded thinking entry falls back to global default, not the per-model override. Startup explicit flags do not implicitly rewrite global defaults. Unavailable/auth-unconfigured saved models can produce a restore warning and fallback.
- CLI /mode is distinct again: src/agent/instruction-mode.ts registerInstructionMode writes bruv-instruction-mode custom session entries and persistedMode restores the latest owned entry on start/refresh. New root session defaults to orchestrator. /mode changes instructions only, not model/thinking/global defaults. Child role is fixed by child metadata rather than root /mode.

## Child profiles (why subagent settings can already restore)

- src/tasks/subagent-profiles.ts profilesPath/loadProfiles/saveProfiles: ~/.bruv/subagents.json holds fast/normal/orchestrator model and thinking configuration. saveProfiles validates then atomically renames a 0600 temporary file. /subagents uses src/tasks/subagent-settings-ui.ts and ui/subagent-settings.ts; Save persists, Cancel discards. Reopening the UI reloads that file. It applies to future launches, not retroactively to already-running/resumed children.
- src/tasks/job-service.ts reads profiles each launch and resolveProfile uses configured model/thinking or parent values. Inherit and worktree launches use the same policy; explicit --model/--thinking select the child. src/tasks/agent-session.ts prepareAgentSession persists bruv-agent identity/ancestry/task metadata; subsequent child transcript saves its actual model/thinking. Resume restores that child's history, not fresh resolution from today's profile defaults.
- Current canonical patch apps/server/src/mcp/BruvDelegationPolicy.ts resolveBruvProfileSelection reads the same file in the backend (BRUV_SUBAGENT_PROFILES_PATH can override), inherits missing thinking from parent options and missing model from parent, and supplies instructionMode=profile plus thinking options. Native backend, not provider text, owns profile/depth authority.
- Named SSH launch src/remote/owner.ts uses DESTINATION ~/.bruv/subagents.json. Missing remote profile model needs configuration or an explicit override; thinking defaults to off if absent. Overrides affect that task, not laptop/default profile files. A remote task records its resolved profile.

## Practical boundaries / genuine gaps

Already persisted: subagent profiles, model options (including web thinking/mode), per-thread permissions/interaction mode, server/project defaults, workspace intent/config and CLI model/thinking session history. Not all of these are intended global last-used preferences. Baseline gap is automatic CLI thinking-default saving after ordinary root TUI picks. Browser sticky preferences do not synchronize across origins/devices or populate CLI defaults. Project overrides can intentionally mask a changed global default. The Bruv rename is a fresh namespace: ~/.die is untouched and is not automatically migrated/read as ~/.bruv. Check namespace/base dir and resume versus new-session scope before diagnosing unsaved state.

Values unchanged: this is a concrete authority/scope audit, not a new general lesson. Existing fix notes deliberately untouched.
