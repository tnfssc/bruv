# Request setup: select indexed records before loading bodies

Follow-up to [full-frame latency](full-frame-latency-followup.md). The full-CLI profile found native-compaction context reads and native-fast setting capture loading unrelated history bodies during submission. This narrow change does not establish full latency acceptance.

The disk history owner now selects candidates using its existing active branch and context metadata traversal. Compaction reads only a compaction at context index zero, not archived checkpoints in the kept range. The context hook reuses that one entry for validation and adaptation; the provider hook still checks serialized opaque replay. Validation happens even when the selected provider is unsupported. Native fast mode selects all matching custom-type records on the active branch, including settings before compaction, then runs the unchanged newest-first identity/schema/cost rules. Volatile opt-out still wins before any history read. Unowned and in-memory managers keep their public-API fallback.

Proof: `tests/native-request-history.test.ts` uses actual published/reopened disk histories and counts every `DiskEntryStore.materialize` call. Unrelated histories cause zero calls in both request paths. A relevant compaction causes one context-hook call and one provider-hook call; lost serialization, invalid details and incompatible providers block. Checks cover compatible model switching, kept archived checkpoints, labels, branches, resets, switched stores, malformed fast identity/schema/cost records, other-scope markers and failed-persistence volatile opt-out. The native-compaction/native-fast/new request-history suites pass 77 tests / 406 assertions. SDK/history projection parity checks pass 2 tests / 27 assertions; TypeScript passes. Bun 1.4.2; dependencies and generated runtime assets reused from the parent, without a build.

Assumptions: disk index type/customType and parent/compaction metadata are authoritative, as for the existing branch/context APIs. The pinned SDK replays only the index-zero compaction. Full branch/context metadata scans remain O(history); all fast-setting candidates are materialized, with no tail cap or scope prefilter of their data. Required SDK request projection, Codex capture cloning and native/unowned full-body fallback remain. No cache, TTL, persistent state, numeric-cache rewrite, history truncation or validation shortcut was added. Parent owns final compiled measurement; renderer/CLI files were not changed.

Values stay unchanged: this applies the existing single-owner, simplest-path, no-quiet-loss and honest-proof guidance.
