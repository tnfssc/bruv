### Replacements and essential retained seams

- **Already replaced by earlier adoption:** custom Pi RPC/resources, broad v2/schema/compiler rewrites, bespoke usage aggregation/cost presentation, codec/syntax adapters and duplicate dependency definitions. [Migration](upstream-first-migration.md) records ~81% patch-byte reduction. Official PiAdapterV2/PiRpc, codecs, orchestration/projections, replay fixtures, usage and MCP injection remain upstream-owned. This main merge replaces **no newly identified remaining production seam** in the compared tree. Do not rebuild those parts or preserve obsolete forks.
- **Keep embedded Bruv identity/environment:** BruvWebPi, binary/settings and profile-mode wiring, Bruv-version exemption limited to the trusted embedded executable, and disabling Pi's updater for that executable. Official Pi RPC spawns an external provider; Pi support does not supply Bruv's executable, profiles or host tools.
- **Keep task security:** BruvTaskService/BruvDelegationPolicy, server-derived depth/profile and durable ancestry, restricted MCP issuance, native task bridge and structured worktree preparation. [Stock registry](https://github.com/pingdotgg/t3code/blob/de343914273eceb852a1d1d739cd1d38df7796ee/apps/server/src/mcp/McpSessionRegistry.ts#L126-L143) still grants baseline orchestration/worktree/pull-request capabilities; it does not replace least-privilege child credentials.
- **Keep launch/delivery/cancellation fixes:** [stock keys](https://github.com/pingdotgg/t3code/blob/de343914273eceb852a1d1d739cd1d38df7796ee/apps/server/src/mcp/OrchestratorMcpService.ts#L475-L539) still use providerSessionId; Bruv makes identity thread-stable across reconnection. Stock async launch/replay can acknowledge terminal delivery; Bruv launch must not consume unread results. [Stock cancel](https://github.com/pingdotgg/t3code/blob/de343914273eceb852a1d1d739cd1d38df7796ee/apps/server/src/mcp/OrchestratorMcpService.ts#L1482-L1553) still interrupts before delivery disposal and rejects nonterminal children without active runs. Keep durable cancel authority/disposal before interruption, subtree ownership and read-only observation. #14636 does not supersede these fixes.
- **Questions are distinct contracts:** official [Pi extension dialogs](https://github.com/pingdotgg/t3code/blob/de343914273eceb852a1d1d739cd1d38df7796ee/apps/server/src/orchestration-v2/Adapters/PiAdapterV2.ts#L19-L24) map to runtime approval/user-input requests. Bruv's [saved questions](../../src/questions/service.ts) preserve owner/version, checkpoints and human answer provenance. They still have **no web projection**; a Pi dialog is not a saved-question answer.
- **SSH is not replaced by app-owned delegation:** retain human-pinned authorization, isolated tracked snapshots/untracked approval, owner-only answers, durable remote IDs and bounded repo capabilities. [Root routing](../../src/tasks/job-service.ts) intentionally rejects named-SSH cross-placement and model/source overrides from scoped native tasks; native/SSH launches are async-only and reject child deadlines. Removing that boundary for apparent parity is not migration. Actual SSH/provider access was not tested here.
- **Keep packaging/product boundaries:** Bruv preload/bootstrap, Bun PTY/optional-search/native asset/local self-reference checks, Host/Origin protections, local-shell notification/Stop fencing, route/reload fixes and five optional stored per-turn cost fields. Stock packages do not provide these or Android packaging. Keep official dependency ownership, not a second catalog.
