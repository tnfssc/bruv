# Failure-boundary probe (experimental, no production edits)

Run `./experiments/remote-failure-probe/run.sh` from any directory. Requires Docker, host Bun and a staged die binary; override `BUN_BIN` / `DIE_BIN` as needed. Strict TS: link installed repository dependencies temporarily and run `tsc -p wisdom/experiments/remote-failure-probe/tsconfig.json`. The runner stages the existing task-poc Dockerfile/owner/bounded-log, not a copy of its runtime; uses synthetic loopback provider, no paid model or credentials/home/socket mounts. Each run uses new Docker image/container/volume and Docker-assigned loopback port. Resources capped at 768 MiB, 2 CPUs and 128 PIDs. HTTP calls have 2.5s timeouts; readiness, gate and start polling bounded; Docker artifact cleaned on exit. `LAB_KEEP=1` retains synthetic diagnostics in a temporary directory on failure (including ephemeral token; do not publish it).

First, TCP gate proxies one POST /launch to the owner and blocks every upstream response byte. Gate only destroys the downstream socket when the owner has responded; owner has fsynced acceptance before replying. Record upstream response and zero downstream bytes, failed client launch and independent owner event inspection. Retry same stable ID/prompt/profile and compare stored resolved config to both retries. Await the actual RPC execute start, check no tool end/outcome, then SIGKILL the container and start the same container on its retained volume. Observe one model turn/acceptance, persisted unknown outcome, epoch increment, no replay; stale replica rejects cross-epoch sync. Force partial JSONL append on a separate replica copy; offline read must fail rather than silently remove the canonical replica. Finally the existing task-poc runner proves that client exit during remote execution does not stop completion, and offline transcript includes two tools and the done outcome. Its independent Docker resources are cleaned by its runner.

Limits: TCP gate measures application socket bytes, not packets or power loss. One accepted launch, not a general exactly-once guarantee across crashes, network partitions or provider side effects. SIGKILL may terminate a tool after side effects and before its result is recorded; `unknown` explicitly does not undo or safely replay it. No repaired/resumed turn and no automatic cross-epoch merge. Partial append test demonstrates detection, not a repair strategy. Local owner append fsync is not a power-failure atomicity proof. This is Linux Docker and a fake model, not a Mac, provider-auth, or large fleet test.
