# Repo handoff slice for integrated remote CLI

This subprocess adapter is for the **same** wisdom/experiments/remote-cli-experience/cli.ts workflow, not a second CLI. The CLI calls python3 repo/handoff.py capture <repo-root> <new-artifact-dir> [explicitly-approved-untracked-paths...] and integrate <repo-root> <manifest> <patch> <persistent-receipts-dir>. The isolated result adapter is also available as result <remote-checkout> <manifest> <patch>; the Docker fixture owner generates the same snapshot-to-worktree Git diff directly. Outputs are JSON. Map local absolute paths in the manifest to remote artifact paths on receipt; never treat them as remote paths. Keep manifest, patch, receipts durable together outside the repo. The CLI accepts only explicitly supplied `--include <exact-path>` flags for untracked files; no native question is treated as transfer permission. Default is no untracked input. Ignored files are not included. Bundle includes reachable Git history: **no historical secret filtering claim**. Review size/sensitivity before transmission.

Snapshot is a commit based on HEAD with **all** tracked staged and unstaged content overlaid, then only explicitly selected regular untracked files. Staging layout is recorded as a fingerprint, not reproduced remotely. Capture rejects unmerged entries, tracked symlinks/gitlinks and a changed capture fingerprint. Return patch is snapshot-to-result tracked worktree (committed, staged and unstaged), not a patch relative to local HEAD; untracked remote creations are not represented by this narrow patch; the CLI reports their paths and refuses automatic integration. No remote untracked byte transfer/review artifact exists yet. Apply refuses HEAD/index/tracked changes since capture, non-regular paths, creation/deletion/mode changes (including remote new files), selected untracked paths, and patches that fail Git apply check. **New files always go to review**, even when their names do not exist locally; future acceptance requires an explicit collision-safe policy. Only regular tracked-file content changes with a matching local fingerprint and clean apply check are automatic. Git apply updates worktree, not index; staged bytes stay staged. No commit, push, shared sync, or user repo mutation during tests.

A receipt keyed by snapshot + patch digest is exclusively created *before* apply, so duplicate attempts return review instead of blindly replaying, including ambiguous crash outcomes. Keep receipts stable across retries. Review retains patch artifact; no forced overwrite. No guarantee of atomic multi-file integration: external writers, simultaneous separate task results, and process interruption during apply are not serialized. Caller must serialize capture/integrate and keep repo quiescent; an uncertain receipt is manual review. Git attributes/filters, sparse checkouts, submodules, hostile Git configurations and hooks, large repo transfer performance, and malicious remote patches need further hardening before production use. This is disposable Git evidence, not a security sandbox.

Run python3 -m unittest discover -s wisdom/experiments/remote-cli-experience/repo -v.
