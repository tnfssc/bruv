# Repository handoff integration

Production module: [repository.ts](repository.ts). The remote owner/client/operations layer must own task IDs, SSH transfer, authentication, final task state, serialization and artifact retention. This module never contacts a host or asks the user a question.

1. Before launch, call `captureRepository(localRoot, newPrivateArtifactDir, approvedUntrackedPaths)`. Show the user exact untracked paths and get explicit approval **before** passing any in the third argument. Default transfers none; ignored files remain excluded. Show `omittedUntracked` and warn that the Git bundle contains reachable **history** (possibly deleted secrets). Do not claim secret scanning. Keep manifest and bundle under a durable task-ID directory outside the repo. Capture does not mutate the local index/worktree. A changed repo during capture throws: discard the artifact, don't launch.
2. Transport `bundle` to the pinned owner over the existing authenticated SSH path, clone it in a task-owned checkout, and verify `git rev-parse HEAD` equals `snapshot` before starting the task with that checkout as cwd. Launch only after successful verification. Avoid shell interpolation; use argument arrays and task-bound paths. The caller owns cleanup when launch fails.
3. Only after task completion, call `collectRepositoryResult(remoteCheckout, snapshot, newRemotePatchPath)` on the owner. Fetch patch bytes + JSON result and persist both under the same task ID. Never infer task completion from patch generation. Verify digest on receipt. The result records remote untracked **names only**: these bytes are not transferred.
4. For return, call `integrateRepositoryResult(localRoot, manifest, resultWithLocalPatchPath, durableReceiptDir)` after preserving the artifact. Present `review` reason and artifact location, not success. Serialize capture/integration per repo, and keep repo quiescent during application. Applied changes go to worktree only; existing staged index stays staged. Receipts prevent automatic retry after ambiguous interruption and must not be deleted on reconnect.

New files, deletions, mode changes, local drift, remote untracked files, invalid/complex patches and duplicate attempts are review, not automatic apply. No atomic guarantee against external repo writers or crashes between files. Git filters, hostile config/attributes, huge repositories, trust in remote owner, and secret-bearing history need further production hardening and deployment policy. Only disposable Git fixtures were tested here; no real host/user repository or provider used.
