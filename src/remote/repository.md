# Repository handoff integration

Production module: [repository.ts](repository.ts). The remote owner/client/operations layer must own task IDs, SSH transfer, authentication, final task state, serialization and artifact retention. This module never contacts a host or asks the user a question.

1. Before launch, call `captureRepository(localRoot, newPrivateArtifactDir, approvedUntrackedPaths)`. Show the user exact untracked paths and get explicit approval **before** passing any in the third argument. Default transfers none; ignored files remain excluded. Show `omittedUntracked` and explain that the bundle contains an orphan current snapshot, not local commit history. Known credential/config paths are rejected; this is not content secret scanning. Keep manifest and bundle under a durable task-ID directory outside the repo. Capture does not mutate the local index/worktree. A changed repo during capture throws: discard the artifact, don't launch.
2. Transport `bundle` to the pinned owner over the existing authenticated SSH path, clone it in a task-owned checkout, and verify `git rev-parse HEAD` equals `snapshot` before starting the task with that checkout as cwd. Launch only after successful verification. Avoid shell interpolation; use argument arrays and task-bound paths. The caller owns cleanup when launch fails.
3. Only after task completion, call `collectRepositoryResult(remoteCheckout, snapshot, newRemotePatchPath)` on the owner. Fetch patch bytes + JSON result and persist both under the same task ID. Never infer task completion from patch generation. Verify digest on receipt. Ordinary regular remote untracked files are included in the review patch, never automatically applied. Sensitive/unsupported paths and oversized outputs stop export with an explicit error; the remote checkout remains available.
4. For return, call `integrateRepositoryResult(localRoot, manifest, resultWithLocalPatchPath, durableReceiptDir)` after preserving the artifact. Present `review` reason and artifact location, not success. Serialize capture/integration per repo, and keep repo quiescent during application. Applied changes go to worktree only; existing staged index stays staged. Receipts prevent automatic retry after ambiguous interruption and must not be deleted on reconnect.

New files, deletions, mode changes, local drift, remote untracked files, invalid/complex patches and duplicate attempts are review, not automatic apply. No atomic guarantee against external repo writers or crashes between files. Clean/smudge-filter repositories and oversized snapshots are rejected. Git runs without global/system configuration; diff disables external diff/textconv. Snapshot/checkouts and transfer artifacts have explicit size/time bounds. The remote SSH user remains trusted, and path-based operations are not a hostile concurrent filesystem sandbox. Verification is disposable Linux Git/Docker fake-provider fixtures, not Mac, real provider or arbitrary user repositories.
